# 技术设计 · 问牍

## 方案概述
浏览器走 Vue 页面；FastAPI 管登录、上传鉴权、去重、解析切片、检索、生成。Postgres 存用户、文件元数据、切片、问答、实例级 LLM 配置。原文件落在**部署机本地磁盘**；浏览器用短时签名 PUT 到同域 `/api/storage/...`，API 不长期中转文件字节。提问时：只检索该用户已完成切片 → 片段不够则直接返回「材料里没有」→ 够则让 LLM **只根据片段** 生成带出处编号的回答。

支持的文档扩展名：`.pdf`、`.md`、`.txt`、`.docx`、`.pptx`、`.csv`、`.xlsx`。Office/表格统一抽成纯文本再切片；不做图片或扫描件 OCR。

## 技术栈（冻结）
- 前端：Vue3 + Vite + Vue Router + Pinia（页面自建；不绑 Element Plus）
- 后端：Python FastAPI
- 数据库：PostgreSQL + pgvector；关键词检索用 Postgres 全文（`simple` 分词）
- 文件：部署机本地磁盘（`FILES_DIR`，默认 `data/files`）；浏览器 PUT 到 `/api/storage/{key}`（短时 HMAC 签名）
- 模型：OpenAI 兼容 Chat + Embedding；配置仅读 `instance_settings` 表（管理页写入）
- 托管：Docker Compose（api + web 静态 + postgres）；Caddy 或 Nginx 终止 HTTPS

明确不用：LangChain / LangGraph / LlamaIndex 当骨架；Redis；Celery；多租户 SaaS 框架；官方对象存储（S3/OSS）实现；SMTP / 邮件找回密码。

## 前后端关系
- **浏览器只面对本站。** 页面是 Vue；业务请求打同域 `/api`（Cookie session）。前端不直连 Postgres，不持有模型 Key。
- **生产同域反代。** `/` 静态前端，`/api` 转 FastAPI。
- **开发同样当同域。** Vite 代理 `/api`。
- **上传：** 浏览器用短时凭证 PUT 到 `/api/storage/...`；`prepare` / `complete`、解析、提问仍只走 API。
- **分工。** 前端展示 `message`；后端管规则与人话。HTTP 层见 `apps/web/src/http/`。

## 备选方案
- **整文件塞进上下文：** 否。必须 RAG。
- **SQLite：** 否。pgvector 与隔离需要 Postgres。
- **文件经 API 中转再存：** 否。浏览器 PUT 直写磁盘。
- **公开注册 + 邮箱激活：** 否。管理员建号；种子管理员由 env 引导。
- **忘记密码 / SMTP：** 否。自托管由管理员重置。
- **官方内置 OSS/S3：** 否。保持仓库云厂商中立；扩展见下。

## 存储扩展（非 v1 官方范围）
`apps/api/app/storage.py` 定义 `Storage` 抽象（`credential` / `get_bytes` / `delete` / `object_exists`）。v1 仅实现 `LocalStorage`。部署者若需 S3/MinIO/OSS，可自行实现接口并替换 `get_storage()`，不在本仓库维护。

## 数据模型
- `users`：id, **email**（唯一，存登录用户名）, password_hash, **is_admin**, created_at
- `instance_settings`：id=1 单行；openai_api_key, openai_base_url, openai_chat_model, openai_embed_model, **embed_dim**
- `files`：id, user_id, filename, ext, content_hash, **storage_key**, status, fail_reason, byte_size, created_at
- `chunks`：id, user_id, file_id, ordinal, text, embedding, tsv
- `conversations`：id, user_id, title, created_at, updated_at
- `messages` / `citations`：messages 归属 `conversation_id`；citations 同前

已移除表/列：`password_reset_tokens`、`email_verification_tokens`、`users.verified_status`。

删除文件：删磁盘对象；级联删 chunks；citations 保留 snippet 并标记 file 已删。

## 账号校验（`accounts.py` / `passwords.py`）
- **登录名：** 2–64 位；小写存储；允许 `[a-z0-9@._-]`；API 请求/响应字段仍叫 `email`（历史兼容）。
- **密码：** 新建/重置至少 6 位，无复杂度；登录只校验非空。
- **校验入口：** `normalize_login()`、`require_login()`、`require_password()`。

## 启动引导（bootstrap）
- `init_db`：`CREATE EXTENSION vector` → `create_all`（按 `models.py` 建表）→ 全文索引 → `bootstrap`。
- **不做**启动时 `ALTER TABLE` 存量迁移；表结构以 `models.py` 为准，新部署直接 `create_all`。
- `bootstrap`：若不存在 `ADMIN_USER` 对应用户则创建管理员；确保 `instance_settings` id=1 存在。
- **默认凭据仅写在 `.env.example`**（`admin` / `admin`）；部署后应在管理页修改密码。

## API
均需登录（HTTP-only Cookie），管理员接口另需 `is_admin`。错误带稳定 `code` + 按语言的 `message`。

| 方法 | 路径 | 成功 | 失败 |
|------|------|------|------|
| POST | `/auth/login` | 登录态 + `{ id, email, isAdmin }` | 账号或密码不对 |
| POST | `/auth/logout` | 空 | — |
| GET | `/auth/me` | 当前用户 | 未登录 |
| GET | `/admin/settings` | LLM 配置（含完整 Key，仅管理员） | 非管理员 |
| PUT | `/admin/settings` | 已保存 | 非管理员 |
| GET | `/admin/users` | 用户列表 | 非管理员 |
| POST | `/admin/users` | 新用户 | 用户名已占用 / 密码太短 |
| PUT | `/admin/users/{id}/password` | 已重置 | 非管理员 |
| DELETE | `/admin/users/{id}` | 已删除 | 不可删自己/管理员 / 用户不存在 |
| PUT | `/admin/me/password` | 管理员改自己密码 | 密码太短 |
| GET | `/files` | 文件列表 | — |
| POST | `/files/prepare` | 秒传或上传凭证 | 类型/过大 |
| POST | `/files/complete` | 进入处理 | 对象不在 |
| PUT | `/storage/{key}` | 写入原文件（短时签名） | 签名无效 |
| DELETE | `/files/{id}` | 空 | — |
| GET | `/ask/conversations` | 对话列表（`updatedAt` 倒序，同活跃则 `createdAt` 倒序） | — |
| POST | `/ask/conversations` | 新建空对话 | — |
| PATCH | `/ask/conversations/{id}` | 重命名（body `title`，trim 后最长 80；空串清空） | 不存在 |
| DELETE | `/ask/conversations/{id}` | 删对话及其中问答 | 不存在 |
| GET | `/ask/conversations/{id}/messages` | 该对话历史 | 不存在 |
| POST | `/ask` | **SSE**；body 须含 `conversationId` | 无 ready / 对话不存在 / … |

已移除：`POST /auth/register`、邮箱激活、`/auth/forgot-password`、`/auth/reset-password`、用户自助改密（非管理页）、配额/熔断、OSS 回调。

## 关键流程
1. **上传：** 鉴权 → 类型/大小 → 同用户哈希去重 → 签发短时 PUT 凭证 → 浏览器写入 `/api/storage` → `complete` → 解析切片 → ready。
2. **提问：** 鉴权 → 校验 fileIds → 检索（Postgres；向量化失败降级关键词）→ 支撑不足则 SSE `done: no_evidence` → 否则流式生成；生成失败/检索异常（非配置类）亦 `done: no_evidence`；正常结束 SSE `done: answer`。
3. **LLM：** `llm.py` 仅读 DB（含 **embed_dim**）；任一必填项缺失则 `LLM_NOT_CONFIGURED`。已有向量材料后不可改 embed_dim。
4. **删用户：** 鉴权 → 禁止删自己/管理员 → 删磁盘 `storage_key` → 删 messages（级联 citations）→ 删 files（级联 chunks）→ 删 usage_daily → 删 user。

## 横切
- 所有查询带 `user_id = 当前用户`
- 前端永不出现模型 Key
- 日志：不含密码、不含文件全文、不记录完整 API Key

## 主路径冒烟
- **脚本：** `apps/web/scripts/e2e-smoke.mjs`
- **命令：** `cd apps/web && npm run e2e`
- **登录：** 默认 `admin` + `admin`（可用 `WENDU_ADMIN_USER` / `WENDU_ADMIN_PASSWORD` 覆盖）
- **覆盖：** 入口、登录、管理建用户、上传、问答、出处、依据不足、管理页
- **不覆盖：** PDF、拖放限定、邮件/SMTP

## 风险

| 坑 | 如何避开 |
|----|----------|
| 默认管理员密码未改 | README 与 `.env.example` 提示；管理页改密 |
| 存量库管理员仍是旧用户名 | `.env` 设 `ADMIN_USER` 为已有用户名，或管理页新建 |
| 磁盘满 | 部署者自管 `FILES_DIR` 卷容量 |
| 模型账单 | 无公开注册；自托管自控 Key |

- 本机开发：`FILES_DIR=data/files`；Vite 代理 `/api`
- 环境变量见 `apps/api/.env.example`
