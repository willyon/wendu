# PRD（Product Requirements Document / 产品需求文档）· 问牍

产品名：**问牍**（英文品牌名 **Wendu**；仓库目录 `wendu`）。牍是文书；问的是你上传的那叠材料，不是全网。

## 对外一句话

上传 PDF、Word、PPT、表格或 Markdown 等文档，对着你的材料提问，答案带出处。

## 定位

**自托管开源产品**：部署者在自己的服务器或本机运行；默认管理员在 `.env` 中配置（见 `.env.example`），首次启动写入数据库。无公开注册、无 SaaS 配额。原文件落在部署机本地磁盘。

## 谁

一种人：手头有几份说明、报告、笔记（PDF、Word、表格等），想问里面写了什么，并且要能核对原文。不是企业知识库管理员，也不是「什么都想问 AI」的闲聊用户。

## 问题

今天把文件丢给 ChatGPT 一类产品，也能总结、也能问。痛点是：回答常混进模型自己的知识，出处不稳定，材料也不在自己这边形成一份可再来的库。值得做成产品的点不是「更会聊」，而是 **只答这批材料、并能点回原文**。

## 目标

第一版必须做成：

- 管理员登录后，在管理页创建普通用户账号；普通用户登录后上传支持的文档类型，处理完成后可提问。
- 回答只依据这批已处理材料；检索支撑不足时，界面明确说材料里没有，不把世界知识当答案。
- 每条关键结论带可点的出处（文件名 + 原文片段）。
- 下次打开还能看到自己的材料和问答。
- 原文件落在部署机本地磁盘（本机或自有服务器，同一套实现）；Docker 下挂载 `data/files`。
- 模型 Key 在管理页配置（存 `instance_settings` 表），不在 `.env` 配置。
- 界面中英可切换；系统文案两种语言齐全。

## 非目标（明确不做）

- 和 ChatGPT 比谁更会总结、闲聊、写作、翻译、多轮角色扮演
- 用模型世界知识补全材料里没有的内容
- 多 Agent、工作流画布、任意网页抓取与「研究一下某某市场」
- Notion / 邮件 / 网盘同步、团队空间、分享链接
- 支付、套餐、公开自助注册、邮箱激活注册流
- 微信小程序（可列入后续路线图，v1 不做）
- MCP、多模态（图问字、扫图）、语音；图片 OCR、扫描件 PDF OCR
- 老版 Word（`.doc`）；要求另存为 `.docx`
- 第二种登录、第二条主路径（生成待办清单、对照 JD 等）
- 第三种界面语言；把用户材料或出处翻译成界面语言
- 每用户文件数上限、每日提问配额、全站熔断

## 成功标准

没看过设计的人，用 **自己的** 3 个文件，在约 3 分钟内：登录 → 上传完成 → 问一个材料里有答案的问题，得到带可点出处的回答；再问一个材料里没有的问题，看到「材料里没有」而不是编造。

## 约束

- 平台：Web 响应式（手机与桌面浏览器）；不做独立桌面客户端、不做 App
- 模型走 OpenAI 兼容接口；Key 与模型名仅在管理页配置，前端永不持有
- 界面语言：第一版仅中英（`zh` / `en`）；不加第三种语言
- 规格与代码在本仓库 `docs/spec/`
