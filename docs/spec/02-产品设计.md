# 产品设计 · 问牍

## 主路径（逐步点击）
1. 打开入口页：左侧看懂一句话，右侧**仅登录**（同页；无公开注册、无忘记密码）。
2. 管理员另可进入 `/admin`：改自己的密码、配置模型（Key / Base URL / 模型名）、创建普通用户、重置他人密码、**删除普通用户**（删账号并清空其全部材料，须确认）。
3. 进入工作台：上传支持的文档，左侧看到每个文件「处理完成」或失败原因
4. 在右侧（宽屏）或「问答」页（窄屏）输入问题；可将左侧 **完成** 文件拖入/点选进提问框以**只针对部分材料**提问；未选则针对全部完成文件
5. 看到回答；每条关键结论旁有出处；点击出处看到文件名和原文片段
6. 退出后再进来：若仍有登录态，**直接进工作台**（不必再过入口页）；仍是自己的文件和历史问答

（入口 / 工作台 / 管理 = 登录后主体验。）

## 三态
- **第一次来（部署者）：** 按 README 起服务 → 用 `.env.example` 默认管理员（`admin` / `admin`）登录 → 管理页改密、配置模型（Key / Base URL / 模型名）→ 可选创建用户 → 工作台空态 → 上传 → 首问
- **普通用户：** 入口登录 → 工作台；忘密由管理员在 `/admin` 重置
- **失败（用户文案）：**
  - 登录失败：「账号或密码不对。」
  - 用户名不合法：「用户名格式不对（2–64 位，仅字母数字及 @._-）」
  - 密码太短：「密码至少 6 位。」
  - 文件类型不对：「只支持 PDF、Word、PPT、Excel、CSV、Markdown 和纯文本。」
  - 太大：「每个文件不超过 20MB。」
  - 上传没成功：「文件没传上去，请再试一次。」
  - 解析失败：「这份文件读不出来，请换一份或另存为支持的格式再试。」
  - 处理中刷新：「还在处理，请稍候。」
  - 检索支撑不足、向量化临时失败，或无法基于材料生成答案：在阅读流内统一展示「抱歉，我在您上传的材料里没有找到足够依据来回答这个问题。您可以换个问法，或确认相关内容是否已在文件中。」**不用顶部 Toast**（上传/入库阶段的向量化失败仍提示管理员检查配置）
  - 模型未配置：「模型尚未配置，请在管理页填写 API Key、Base URL、模型名称与向量维度。」（Toast）

## 对象与规则
- **资料库：** 属于单个用户。第一版只有一个资料库，不建多项目。
- **文件：** 支持 `.pdf`、`.md`、`.txt`、`.docx`、`.pptx`、`.csv`、`.xlsx`；单文件 ≤ 20MB；**无每用户文件数量上限**。不支持图片、扫描件 OCR、老版 `.doc`。表格与幻灯片抽成纯文本后再切片；出处仍是「文件名 + 文本片段」。**失败不占去重逻辑**，同哈希失败可重试。同一用户、内容相同（按文件哈希）再传：已成功则秒传；处理中则继续等。不按文件名去重，不跨用户去重。
- **存储：** 原文件落在部署机本地磁盘（环境变量 `FILES_DIR`，默认 `data/files`）。支持本机部署与自有服务器部署（同一实现；远程访问靠 HTTPS 暴露 API，不靠对象存储）。官方不提供 S3/OSS；需要者可实现 `storage.Storage` 接口自行扩展。
- **问答：** 只检索该用户已「处理完成」的文件；可选 **`fileIds`** 限定子集（须均属当前用户且 ready）。**每一问独立检索**；同一对话内的历史只展示，不把上文当世界知识。是否够格回答 **仅看检索分数**（向量/关键词命中），**不用问题黑名单或停用词表**。生成时必须带检索到的片段；支撑不足或与材料无关（由模型按 Prompt 自判）走「材料里没有」文案。回答语言与提问一致；问「能答什么/能做什么」时 **2–4 句**概括主题。
- **对话（多会话）：** 用户可有多个 **对话**；每个对话独立保存问答记录，**共用同一资料库**（不绑定文件子集）。支持 **新建 / 切换 / 重命名 / 删除** 对话；列表按 **最近问答活跃**（`updatedAt`）倒序，相同时按 **创建时间**（`createdAt`）倒序；**重命名、切换不算活跃**。标题默认取该对话**首问前 24 字**（无问法显示「新对话」）；用户可手动改名（最长 80 字；清空则交回自动标题）。删除对话只删其问答，**不删文件**；删除前须站内确认框（非浏览器原生 `confirm`）。
- **出处：** 每条关键结论至少一条出处：文件名 + 片段原文。点开能看到片段。不允许无出处的关键结论。
- **世界知识：** 禁止用材料外的知识充当答案。允许的话术只有「材料里没有 / 依据不足」。
- **语言：** 系统文案随界面中英切换；材料与出处保持原文、不翻译。生成回答使用用户提问所用语言。切片、存储与界面语言无关。检索不按界面语言分叉，也 **不以中文分词器为前提**。

## 产品层（地板）
- **账号：** 无公开注册、无邮件找回。首次启动根据 `ADMIN_USER`（登录用户名）/ `ADMIN_PASSWORD` 创建**一名管理员**。管理员在 `/admin` 创建普通用户并重置密码。
- **登录名：** 2–64 位，小写存储；允许字母、数字及 `@._-`；**不要求邮箱格式**。
- **密码：** 新建与重置时 **至少 6 位**，无复杂度要求；登录只校验非空。
- **隔离：** 一切文件、切片、问答按 `user_id` 过滤；接口不得靠「猜 ID」读到别人的。
- **隐私：** 不设独立说明页。入口左栏品牌下方一行写清：上传的文件只用于为你生成回答，不会用于其它途径。
- **语言：** 第一版仅中英。默认跟浏览器（`zh*` → 中文，否则英语）；用户切换后记住。
